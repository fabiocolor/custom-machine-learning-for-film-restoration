## CWC compute and storage

Read [CWC.md](CWC.md) before any render, training, dataset or compositing step. It is generated by `cwc-onboard-project` and refreshed by `cwc-refresh-client-help`; do not edit it.

- Credentials: `.env.local` (`CWC_BASE_URL`, `CWC_API_KEY`). Never print, log or commit them.
- Controller: load `CWC_BASE_URL` and the project API key from `.env.local` or the approved client environment. Obtain the current service URL from CWC client configuration; never select a worker or infer a route from a previous job. Verify authenticated `GET /readyz` and `GET /api/help` through that URL. Client job routes are `/jobs`, not `/api/jobs`. Do not resubmit accepted jobs during a service URL migration.
- Compute runs as CWC jobs on workers. This host only orchestrates.
- Never copy original footage here. Reference it with `shared_storage_id` plus `relative_path` (`video_slice` for movies, `package_dpx_sequence` for DPX scans).
- Project-only files go through `POST /api/uploads`. Chain steps through CWC artifacts.
- Fetch `GET /api/help` (or MCP `client_help`) at every experiment session. Follow `examples.experiment_proxy` and `examples.experiment_steps`: iterate on storage-prepared half-width/half-height proxies, then rerun a separate quality pass from full-size originals. New experimental staged inputs must total at most 256 MiB, including code/config; CWC rejects oversized or unmeasured references before transfer. Named/raw experiments declare experiment_id or media_phase=experiment. A quality pass requires media_phase=quality_pass and proxy_experiment_job_ids referencing completed bounded experiments from the same source_project; never use that phase for routine inspection. Keep aspect, frame/geometry mapping, original lineage and mask/parameter scaling.
- Experiments use the experiment profile or a `comfyui_graph_v1` raw graph; a new variant needs no ticket.
- If CWC lacks a route, stop and report it. Never fall back to local compute or local copies.

## Owner direction: unavailable historical artifacts (2026-09-27)

Historical outputs may be lost. A completed job or resolved ticket does not prove its artifacts still exist.

1. Perform a bounded check through CWC: list the job's current artifacts, refresh expired download URLs, and inspect available canonical retention/recovery evidence. Ask the existing incident ticket for recovery status if unclear. Do not access workers directly or repeatedly poll an empty completed job.
2. If the required output cannot be found or recovered, the project is authorized to recreate it from scratch through NEW CWC jobs. First check whether an equivalent replacement is already queued, running or available; reuse it instead of duplicating compute. Regeneration is project iteration, not a new recovery meta-ticket.
3. Preserve the old job/history. Use a new idempotency key for a genuinely new submission and keep that key stable on retries of that submission. Record original and replacement job IDs, source references, workflow/code/model versions, seeds and parameters in project provenance and the existing incident ticket. Reuse any verified surviving inputs or intermediates.
4. Follow the current proxy-first contract and 256 MiB experimental input limit: prepare compact, aspect-preserving working proxies on source-local storage agents. A full-quality rerun is a separate explicit quality pass from originals under the live contract. Never pull original DPX sequences onto the research host or relabel routine inspection as a quality pass.
5. A replacement is usable only after CWC stores the required artifacts and their names, sizes and checksums are verified. Keep required downstream inputs/results under explicit retention. Report unavailable originals, missing workflow provenance or a new execution failure on the existing blocker; do not invent missing inputs or claim regeneration succeeded.

## Experiment records and generated results

- Keep experiment code, plans, journals, review decisions, compact manifests, CWC job/artifact IDs, and checksums in this Git repository.
- For new work, put generated media, bounded downloaded review copies, intermediate arrays, caches, and model payloads under `../EXPERIMENT_RESULTS/custom-machine-learning-for-film-restoration/` in the shared RESEARCH folder, outside this Git repository. Resolve that folder from local configuration or `RESEARCH_RESULTS_ROOT`; do not hard-code a machine path.
- Record result-store-relative paths and hashes in repository manifests. Canonical CWC artifacts, source media, retention, and scientific approval remain under their existing authorities. Existing repository-local results are historical until individually inventoried and moved; update active read paths before relying on a moved result.

## Enforced storage and portable artifact custody

- Follow `.research/README.md`. Runnable code stays in existing code directories; new compact custody records go in `experiment_records/`, separately from code. Historical record paths remain evidence.
- All new or changed payload writers must validate their destination through `scripts/research_storage.py` before writing. Missing result-store configuration is a hard stop; never create a repository-local fallback or guess a device mount path.
- Record an accepted CWC job immediately with `research_artifacts.remember_job()`. Use `scripts/research_artifacts.py collect/locate/resume` to reconcile by job/artifact ID and verified shared-store-relative path. Record sources/intermediates by canonical storage references and hashes. A completed job is not proof of artifact custody.
- On every device install `.research/hooks` with `python3 .research/install.py`. Commit/push checks and CI reject new media, models, arrays, archives, binary payloads, reserved result directories and files above the 1 MiB compact-record limit. The local check includes ignored files. Never bypass hooks or regenerate historical exemptions to pass.
- Resume collection of the recorded job after an outage. Do not rerun inference, search alternate machine paths, select workers or repair infrastructure. Retain exact missing IDs and the incident ticket ID. Distinguish local sync delay, CWC finalization, service outage and CWC-reported unavailability; none alone proves permanent loss. Byte custody and scientific approval remain separate.
