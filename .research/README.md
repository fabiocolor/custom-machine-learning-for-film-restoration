# Enforced experiment storage and custody

Runnable code stays in `scripts/` or the project's existing code directories.
New compact custody records stay in `experiment_records/`. Historical records
keep their paths. Generated bytes live only in the configured external store.

On each device, configure `RESEARCH_RESULTS_ROOT` to its existing synced
`EXPERIMENT_RESULTS` directory, or put `{"results_root": "../EXPERIMENT_RESULTS"}`
in ignored `.research/storage.local.json`. Then run `python3 .research/install.py`.
There is no default inside the checkout. Windows and Linux configure their own
root; manifests contain POSIX relative paths, never a device's absolute path.
Compatibility symlinks are historical read conveniences, not new write defaults.

Git pre-commit checks the complete index and local files, including ignored files.
Pre-push checks outgoing tips. CI checks the committed tree. New payloads are
rejected by extension, reserved directories, binary content or the 1 MiB compact
record limit. Already tracked payloads are grandfathered only at their exact Git
blob hash in `storage-policy.json`; new or modified payloads require external
storage. Installation on this machine inventories existing local evidence in a
per-worktree Git-local file. It does not move or delete anything. A fresh checkout
has no exemption for new local payloads. Never regenerate exceptions to pass a
check, disable hooks, use `--no-verify`, or add payload ignore exceptions.

New or changed payload writers must call `research_storage.payload_path()` or
`require_payload_path()` before opening output files. The latter accepts old
relative paths only if they resolve into this project's configured result store.

Immediately after CWC accepts an experiment, call
`research_artifacts.remember_job(job_id, experiment_id)` or
`python3 scripts/research_artifacts.py expect JOB_ID --experiment-id EXPERIMENT_ID`.
This records the accepted identity before polling. Once artifact IDs are known,
`python3 scripts/research_artifacts.py collect JOB_ID` records canonical names,
sizes and hashes before downloading. It streams bounded copies, verifies them,
and atomically publishes each payload and receipt at:

`<project>/artifacts/<job_id>/<artifact_id>/<filename>`

`python3 scripts/research_artifacts.py locate JOB_ID ARTIFACT_ID` checks the
expected bytes on the current device. It never searches other folders. A synced
record from another device is not proof the bytes have arrived here. No artifact
is considered present until its size and SHA-256 match. `resume` reconciles all
outstanding recorded jobs once and is suitable for a device-local timer. It never
submits inference or repairs workers. Default copied-artifact limit is 256 MiB;
large artifacts stay canonical-only until an explicit bounded-copy decision.
Original sources and full-quality masters retain existing CWC storage authorities.
Persist intermediate input references by CWC job/artifact ID or canonical
`shared_storage_id` plus relative path and checksum, not a machine's mount path.
Use `research_artifacts.py reference` to record such a dependency. Existing
device-specific paths in historical evidence are never new lookup instructions.

On one designated collector device per project, run
`python3 .research/install_collector.py`. It installs a two-minute user timer on
Linux, or a scheduled task on Windows. Other devices use `locate` against their
synced copy and can explicitly `collect` a missing copy. Do not install competing
writers on every synced device. Only recorded jobs are reconciled; register an
already accepted job with `expect` to resume custody without resubmitting it.

States distinguish accepted work, awaiting artifacts, verified local copies,
bounded canonical-only artifacts, empty failed jobs, unavailable CWC downloads
and service outages. A completed producer with an empty artifact list is still
`awaiting_artifacts`. A 404 or missing local file alone does not prove permanent
loss. Retain IDs and the incident ticket ID; CWC decides recoverability. Collection
can resume after an outage without rerunning compute. Byte custody does not grant
scientific inspection, normal-speed review or owner approval.

These checks protect normal execution and Git workflows. Git hooks can be bypassed
by an administrator, and arbitrary programs can write files without using the path
API; this is not an operating-system write sandbox. Required remote status checks
must be configured separately if administrative bypass protection is needed.
